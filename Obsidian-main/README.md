# MonHub

Библиотека интерфейса для Roblox Luau: контролы, темы, конфиги, галереи, отдельные окна и необязательные аддоны. Полный API и настройки описаны в [GUIDE.md](GUIDE.md).

> Рекомендуется всегда использовать актуальные файлы библиотеки и обновлять `Library.lua`, `Example.lua`, `addons/SaveManager.lua`, `addons/ThemeManager.lua` и остальные используемые аддоны вместе. Номер релиза закреплён как `0.0.1-release-3`, поэтому одинаковый номер не гарантирует одинаковый набор исправлений. После обновления полностью перезапустите скрипт.

## Что исправлено в системе конфигов

- Временные файлы теперь заканчиваются на `.json` или `.txt`. Устранён путь вида `config.json.tmp`, на котором файловые API с ограничением расширений возвращают `writefile: illegal path`.
- Перед перезаписью проверяются временный файл и резервная копия. Если запись повреждает основной файл или прерывается с ошибкой, менеджер пытается вернуть предыдущие данные и проверяет восстановление.
- Groupbox с одинаковым названием в разных вкладках сохраняются независимо и больше не блокируют загрузку друг друга.
- Значения отключённых контролов восстанавливаются с сохранением их состояния `Disabled`.
- Числовые значения слайдеров проверяются перед изменением UI. Множественный выбор сохраняется списком значений, включая числовые варианты.
- Ошибки синхронных callback при восстановлении передаются SaveManager. Ошибка применения возвращает `false` и запускает откат, даже если часть параметров уже была восстановлена.
- Новый конфиг сразу выбирается в списке. Его можно сразу назначить для автолоада.
- Автолоад читает назначение с диска после повторного запуска и различает отсутствие назначения, частичную загрузку и ошибку.
- Загрузчики Example и QuickStart используют свежий ключ запроса. Example проверяет, что загруженный модуль возвращает таблицу, и отдельно сообщает об ошибке автолоада.

Исправления файловой записи применены также к пользовательским темам. Проверены локальная компиляция и автоматические тесты с эмуляцией отказов записи. Эти проверки не заменяют запуск в конкретной среде Roblox.

## Использование без дополнительного кода

В полном [Example.lua](Example.lua) откройте `UI Settings` и блок `Configuration`.

1. Выставьте нужные настройки.
2. Введите имя, например `Main`, и нажмите `Create config`.
3. Новый конфиг будет выбран автоматически. Нажмите `Set as autoload`, чтобы загружать его при следующих запусках.
4. После изменения настроек нажмите `Overwrite config`. Назначение автолоада само по себе не сохраняет последующие изменения.
5. Для ручного восстановления выберите конфиг и нажмите `Load config`.
6. `Reset autoload` отключает автоматическую загрузку, сохраняя сам конфиг. `Delete config` удаляет выбранный конфиг и очищает его назначение автолоада.

Импорт JSON применяет настройки в текущем запуске. Чтобы сохранить импорт на диск, затем создайте или перезапишите конфиг. Экспорт формирует JSON текущих настроек; при наличии API буфера обмена он также копируется туда.

## Подключение в собственном скрипте

Сначала создайте все контролы и зарегистрируйте адаптеры аддонов. Затем создайте блок конфигурации и вызовите автолоад последним.

```luau
local BASE = "https://raw.githubusercontent.com/SoftRatatui/Obsidian-main/main/Obsidian-main/"
local CACHE = "0.0.1-release-3-configs-2-" .. tostring(os.time())
local Library = loadstring(game:HttpGet(BASE .. "Library.lua?monhub=" .. CACHE, false))()
local SaveManager = loadstring(game:HttpGet(BASE .. "addons/SaveManager.lua?monhub=" .. CACHE, false))()

local Window = Library:CreateWindow({
    Title = "My interface",
    Center = true,
    AutoShow = true,
})
local Main = Window:AddTab("Main", "house")
local Settings = Window:AddTab("Settings", "settings")
local Controls = Main:AddLeftGroupbox("General")

Controls:AddToggle("FeatureEnabled", {
    Text = "Enabled",
    Default = false,
})
Controls:AddSlider("FeatureStrength", {
    Text = "Strength",
    Default = 50,
    Min = 0,
    Max = 100,
    Rounding = 0,
})

SaveManager:SetLibrary(Library)
SaveManager:SetFolder("MyInterface")
SaveManager:SetSubFolder(tostring(game.PlaceId))
SaveManager:IgnoreThemeSettings()
SaveManager:BuildConfigSection(Settings)

local Loaded, ErrorMessage, Report = SaveManager:LoadAutoloadConfig()
if not Loaded then
    warn("Autoload: " .. tostring(ErrorMessage))
end
```

Используйте постоянные ID: `FeatureEnabled` должен означать одну и ту же настройку при следующих запусках. Не меняйте папку между сохранением и загрузкой. Подпапка `game.PlaceId` изолирует конфиги разных мест; для общего набора конфигов используйте одну постоянную подпапку.

`IgnoreThemeSettings()` оставляет выбор темы независимым от игровых конфигов. Если тема должна храниться внутри конфигурации, не вызывайте этот метод и создайте ThemeManager до автолоада.

## Результаты операций

| Вызов | Результат |
| --- | --- |
| `Save(name)` | `success, error` |
| `Load(name)`, `LoadJSON(json)` | `success, error, report` |
| `SaveJSON(name)` | `json, success, error`; порядок отличается от `Save` |
| `SaveAutoloadConfig(name)` | `success, error`; назначает уже сохранённый конфиг |
| `GetAutoloadConfig()` | `name, configured, error` |
| `LoadAutoloadConfig()` | `success, error, report` |
| `Delete(name)`, `DeleteAutoLoadConfig()` | `success, error` |

`report.Applied` показывает число применённых записей, `Skipped` число пропущенных, `Missing` число отсутствующих или несовместимых контролов, `MissingIds` их ID. Игнорируемые настройки тоже попадают в `Skipped`. На неудачной загрузке `Applied` отражает попытку применения до отката и не означает успешное сохранение этих изменений.

У успешного вызова автолоада есть `Status`: `Loaded`, `Partial` или `NotConfigured`. Первый запуск без назначенного конфига возвращает `true` и `NotConfigured`, без уведомления об ошибке. Если в конфиге есть записи, но ни одного подходящего контрола, загрузка возвращает `false`. Обычно это означает, что автолоад вызван слишком рано или загружены файлы с другим набором ID.

Параметры восстанавливаются в порядке: ввод, списки, слайдеры, цвета, переключатели, клавиши, groupbox, адаптеры. Когда один callback должен заполнить список для другого, задайте порядок через `SetLoadingOrder(true, { "Category", "SelectedItem" })`. Указанные ID выполняются первыми.

## Файлы и восстановление

В Example конфиги находятся в `MonHub/settings/<PlaceId>/` внутри рабочей папки файлового API.

| Файл | Назначение |
| --- | --- |
| `Main.json` | Основной конфиг |
| `Main.pending.json` | Временная запись до проверки |
| `Main.backup.json` | Предыдущее содержимое перед перезаписью |
| `autoload.txt` | Имя назначенного конфига |
| `autoload.pending.txt`, `autoload.backup.txt` | Служебные файлы назначения автолоада |

Служебные файлы не отображаются в списке конфигов. Имена `autoload`, имена с окончаниями `.pending` и `.backup`, а также пути с `/`, `\` и запрещёнными символами не используются как имена конфигов. Вводите имя без `.json`, например `Main`.

При сбое записи менеджер сначала пробует восстановить основной файл сам. Если восстановление тоже не удалось, сообщение содержит путь резервной копии. Скопируйте её содержимое в поле `Config JSON`, импортируйте и сохраните под новым именем. Перед ручными действиями сохраните копии файлов. Автоматического отката внешних сетевых действий или задач, запущенных callback через `task.spawn`, нет; такие callback должны быть повторяемыми и управлять состоянием через контроллер.

## Ошибки и уведомления

| Сообщение | Что сделать |
| --- | --- |
| `writefile: illegal path` | Обновите Library, Example, SaveManager и ThemeManager вместе и перезапустите скрипт. Если ошибка остаётся, проверьте указанный путь и права файлового API. |
| `Filesystem API is unavailable` | Нужны `isfolder`, `isfile`, `makefolder`, `readfile`, `writefile`. В среде без них используйте JSON импорт и экспорт. Для списка файлов нужен `listfiles`, для удаления конфига `delfile`. |
| `Config file does not exist` | Проверьте папку и подпапку, затем обновите список. |
| `Autoload failed` | Проверьте существование выбранного конфига и назначьте его через `Set as autoload` заново. |
| `Autoload incomplete` | Часть настроек отсутствует в текущем UI. Обновите все используемые файлы вместе, проверьте ID и порядок создания контролов. |
| `Cannot snapshot current settings` | Исправьте сериализацию текущего контрола или `Adapter.Save`; загрузка ещё не изменила настройки. |
| `Failed to load config data` | Сообщение указывает запись или callback. Исправьте причину и повторите загрузку; менеджер пытается вернуть предыдущее состояние. |
| Ошибка скачивания или компиляции модуля | Проверьте доступ к исходному URL. Обновите загрузчик и аддоны до актуального состояния из одного источника. |

Сообщения конфигурации используют шрифт и стиль библиотеки. У них отдельные заголовок, описание и тип результата. Автолоад показывает количество восстановленных и пропущенных настроек; ошибки не маскируются сообщением об успешной полной загрузке.

Для своих действий используйте тот же формат:

```luau
local Saved, ErrorMessage = SaveManager:Save("Main")
Library:Notify({
    Title = Saved and "Config saved" or "Could not save config",
    Description = Saved and "Main is ready for the next launch." or tostring(ErrorMessage),
    Variant = Saved and "Success" or "Error",
    Time = Saved and 3 or 6,
})
```

## Проверка и обновления

```powershell
./tests/check.ps1 -Compiler luau-compile -Runtime luau
```

Проверки охватывают конфиги, автолоад после повторной инициализации, кнопки конфигурации, одинаковые groupbox в разных вкладках, отключённые контролы, числовой множественный выбор, ошибки callback и повреждение файла во время записи. Файловая модель намеренно запрещает расширение `.tmp`.

Перед обращением с ошибкой рекомендуется обновить все используемые компоненты до последнего состояния репозитория, перезапустить скрипт и сохранить точный текст ошибки. Для отчёта полезны название операции, используемый загрузчик и путь конфига без его приватного содержимого.
